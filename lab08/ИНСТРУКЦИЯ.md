# Переносимый набор ЛР7–9 и ЛР14

Скопируйте рядом папки `lab07`, `lab08`, `lab09`, `lab14`, сохраняя имена. Для отдельного полного состава демонстратора нужны также ЛР12 и ЛР13: ссылки на них в карточке ЛР14 без этих папок не работают. Версия модели карточки — **A13-alpha-2.0**, не 1.0. Данный набор — локальные учебные материалы, не подтверждение согласования адаптации Wine → «Кайдзен», сдачи или права публичной передачи.

## Состав и границы

- ЛР7: README, `analyze.py`, `settings.json`, `metrics.csv`. Исходные 10 TN + 10 FN по отдельным записям не передаются: права не подтверждены, согласуйте безопасный канал или допустимую замену. Метрики — агрегаты.
- ЛР8: README, `check.py`, `СЕГМЕНТЫ.csv`, эта инструкция и запись проверки. Матрица и ручная десятка также в README. Для ЛР14 используется та же агрегированная таблица.
- ЛР9: README, `experiment.py`, `test_experiment.py`, `запуск.txt`, `ПЛАН_исходный.md`, `ЖУРНАЛ_исходный.md`, `ДОКАЗАТЕЛЬСТВА.md`. Исходный план и журнал сохранены как исторические свидетельства; команда в них относится к исходной рабочей папке.
- ЛР14: Model Card, риск-реестр и приложение по сегментам. Проверка полной версии демо — отдельно в ЛР13, включая зависимости его манифеста на ЛР12.

В комплекте нет `kaizen_v1.csv`, сохранённых построчных прогнозов и отдельных примеров. Наличие доступа к ним не означает разрешения передачи или публикации. Агрегаты также передавать только по допустимому каналу.

## Проверка без закрытых входов

Нужен Python 3.10+ со стандартной библиотекой. Из папки `lab08`:

```sh
python3 -B check.py
```

Ожидаются n=479, TN=102, FN=377; n=580, TN=445, FN=135 и общая матрица TN=547, FP=0, FN=512, TP=0. Это проверка согласованности сохранённых агрегатов, **не** доказательство их происхождения из исходных строк.

Из папки `lab09`:

```sh
python3 -B -m unittest -v
```

Ожидаются 2 теста OK; это синтетические проверки функций, не повтор обучения. На Windows используйте `python` вместо `python3`.

## Полный повтор при разрешённом доступе

Получите отдельно оба неизменённых локальных файла, храните и обрабатывайте их в защищённой среде. Из `lab08`:

```sh
python3 -B check.py --data "/путь/к/kaizen_v1.csv" --baseline "/путь/к/validation_predictions.csv"
```

Оба хеша сверяются до чтения; дополнительно сопоставляются строки, проверяются первые 10 и агрегаты. Вывод — только суммы, новые файлы не создаются. Из `lab09` с теми же путями:

```sh
python3 -B experiment.py --data "/путь/к/kaizen_v1.csv" --baseline "/путь/к/validation_predictions.csv"
```

Ожидаемый агрегированный вывод — `lab09/запуск.txt`; test для эксперимента не оценивается. При несовпадении хеша остановитесь и согласуйте новый выпуск; не меняйте контрольные хеши ради прохождения. Для ЛР7 `analyze.py` пишет также построчные случаи, поэтому запускайте только в отдельной защищённой копии с `data/kaizen_v1.csv` после самостоятельной проверки SHA-256 из README; никогда не выкладывайте созданную папку автоматически.

Локальная проверка настоящей переносимой копии и её пределы зафиксированы в [ПРОВЕРКА.md](ПРОВЕРКА.md).
