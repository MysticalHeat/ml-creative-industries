# ЛР11. Минимальный локальный ML-модуль

Модуль принимает учебный идентификатор и возвращает структурированный результат константной модели ЛР7. Это **только техническая демонстрация**, не индивидуальный прогноз, не факт и не основание автоматического решения. На validation BA 0,50, recall класса 1 0: все наблюдавшиеся положительные случаи пропущены. Эксперимент ЛР9 не прошёл критерий и в модуль не включён.

## Установка и запуск

Python 3.10+, стандартная библиотека, установка пакетов и доступ в сеть не нужны. Из папки комплекта:

```sh
python3 -B -m unittest -v
python3 -B examples.py
printf '%s' '{"schema_version":"1.0","request_id":"demo-001"}' | python3 -B baseline.py
```

На Windows используйте `python`; `examples.py` и тесты не требуют `printf`. Проверено на Python 3.14.6. [примеры.jsonl](примеры.jsonl) — полный фактический вывод `examples.py`; входы синтетические. Первые шесть случаев исполняются в отдельных процессах, последний — отдельный вызов функции с отсутствующей моделью.

## Контракт

Один UTF-8 JSON-объект на stdin до EOF; два обязательных поля и никаких других: `schema_version` = строка `"1.0"` и `request_id` — 1–64 символа ASCII из `A-Z`, `a-z`, `0-9`, `_`, `-`. Повторные ключи не допускаются. Используйте только синтетические ID, не персональные данные. Объём stdin не ограничен программой: не использовать на недоверенном сетевом входе.

Результат: один JSON в stdout. При успехе статус `ok`, `model_id`, объект `prediction` с целевой переменной `implemented_90d` и классом 0, список `limitations`. Класс 1 означает зарегистрированную реализацию в дни 0–90; класс 0 — отсутствие регистрации в полном окне; ответ модели — не установленный факт. Ошибка `invalid_input` возвращает только безопасный ID либо null, без прогноза; ошибка `model_unavailable` — без прогноза, с рекомендацией ручного рассмотрения вне модуля. Коды процесса: 0, 2 и 3 соответственно. Состояния поиска `no_matches` нет: модуль не выполняет поиск.

Интеграция: `from baseline import handle`; `handle(json_bytes_or_str, model_path=None)` возвращает словарь. `model_path` позволяет проверить отказ; по умолчанию читается `model.json` рядом с кодом. Контракт ЛР10 — предложение, не подтверждённый организационно регламент.

## Сложные случаи

| Вход | Ожидание | Фактический результат |
|---|---|---|
| `demo-001` | ok, класс 0 | ok, класс 0 |
| ID из 64 символов `a` | ok | ok |
| ID из 65 символов `a` | invalid_input, ID null | invalid_input, ID null |
| `{}` | invalid_input | invalid_input |
| числовой ID 42 | invalid_input | invalid_input |
| дополнительное поле при корректном ID | invalid_input, безопасный ID сохранён | invalid_input, ID `demo` |
| модель отсутствует | model_unavailable, нет прогноза | model_unavailable, нет прогноза |

Полные входы и ответы — в [примеры.jsonl](примеры.jsonl). Тесты также проверяют пустой ввод, неправильный JSON, UTF-8, дубли ключей, версию, посторонние символы и изменение файла модели. Синонимы и неизвестный язык не применимы к контракту идентификатора.

## Версии, конфигурация и границы

`model.json` — вынесенный артефакт `baseline-lr07-kaizen-v1`, сериализация большинства train 0 (3254 против 3050), не сохранённый estimator. Содержит цель, правило и класс. Код проверяет его хеш и ожидаемые значения. [manifest.json](manifest.json) фиксирует хеши включённых файлов и происхождения; хеши отсутствующих исходных файлов не проверяются локальными тестами. Это контроль целостности, не цифровая подпись.

Для обратной совместимости в коде намеренно закреплены схема 1.0, формат и лимит ID, ожидаемая модель, её хеш, список ограничений и тексты ошибок; они являются **неизменяемыми параметрами данного контракта**, а не пользовательскими настройками. Их изменение потребует новой версии кода, проверки и согласования интеграции. Сетевых адресов, ключей, секретов, генеративного prompt template и retrieval-контекста нет. Модуль не читает данные заявок и не использует индивидуальные признаки, не ведёт журнал, не отправляет заявки эксперту и не объясняет индивидуальный результат.

`baseline.py` сохранён побайтно относительно исходного модуля: SHA-256 `9b7adfa9a2b9d4f992da40fc999a43079b82da6c323baec96b6e6aacb9a829e6`. API `handle` сохранён. 24.11.2026 в отдельном временном каталоге с копией исходной ЛР13 и этой редакцией ЛР11 прошли 4 теста демонстратора на Python 3.14.6. Этот комплект сам по себе не заменяет выпуск демонстратора и не изменяет его хеши. Проверка другого устройства/учётной записи преподавателя и организационное согласование не подтверждены.
